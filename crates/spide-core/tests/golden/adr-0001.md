# 1. How do we vary loan rules?

* Status: accepted
* Decision: D1 in Spide design "Library"
* Date: 2026-01-01

## Context and Problem Statement

How do we vary loan rules?

Each term brings a new loan type.

## Decision Drivers

* Evolvability (quality): new loan types each term
* Simplicity (constraint)

## Considered Options

* A — Loan policy strategy
* B — Switch on loan type

## Decision Outcome

Chosen option: "Loan policy strategy".

User notes: New loan types only add a LoanPolicy class, serving Evolvability.

### Consequences

* Architecture health 100 → 90
* Added: class LoanPolicy; Loan —association→ LoanPolicy
* Bad, because it introduced: Member is not connected to anything

## Pros and Cons of the Options

### A — Loan policy strategy

LoanPolicy interface with one class per loan type

* Good, because new loan types without touching Loan
* Bad, because one more abstraction
* Helps Evolvability
* Hurts Simplicity — extra interface

### B — Switch on loan type

* Helps Simplicity
